# Task 3 Identify Constraint Violations
|ID |Constraint|Violation Scenario                                                                                |Variable Values                                                                                                        |Why Violated                                   |Expected Detection & Response                                                                                                         |
|---|----------|--------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------|-----------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------|
|V1 |C1        |The controller opens a barrier while the last carriage is still crossing.                         |`Train_Present=TRUE; Barrier_Open=TRUE`                                                                                |`TRUE → FALSE` is FALSE.                       |Detect using validated readings, feedback, logs, and timestamps. Block opening, maintain warnings/road stop, and raise a safety fault.|
|V2 |C2        |An approaching train is detected, but both warning outputs remain off.                            |`Train_Approaching=TRUE; Warning_Lights_On=FALSE; Audible_Alarm_On=FALSE`                                              |`TRUE → (FALSE ∧ FALSE)` is FALSE.             |Activate warnings. If unavailable, inhibit train permission and escalate the fault.                                                   |
|V3 |C3        |The controller issues a barrier-close command before completing the warning stage.                |`Close_Command=TRUE; Warning_Stage_Complete=FALSE`                                                                     |`TRUE → FALSE` is FALSE.                       |Reject the premature command and complete the warning stage before closing.                                                           |
|V4 |C4        |A barrier reopens while a train is passing because the state machine resets.                      |`Train_Passing=TRUE; Barriers_Closed_Confirmed=FALSE`                                                                  |`TRUE → FALSE` is FALSE.                       |Maintain road stop/warnings, inhibit permissions, and report loss of closure.                                                         |
|V5 |C5        |An old clearance indication causes an opening request while another train is approaching.         |`Open_Command=TRUE; Train_Approaching=TRUE; Clearance_Confirmed=FALSE; Train_Present=FALSE`                            |`TRUE → (FALSE ∧ FALSE ∧ TRUE)` is FALSE.      |Reject opening until fresh clearance confirms no tracked train or approach.                                                           |
|V6 |C6        |Train permission is granted even though the barrier has not reached its closed position.          |`Train_Permission=TRUE; Warning_Lights_On=TRUE; Audible_Alarm_On=TRUE; Road_Stop=TRUE; Barriers_Closed_Confirmed=FALSE`|`TRUE → (FALSE ∧ TRUE ∧ TRUE ∧ TRUE)` is FALSE.|Withhold permission until actual closed-position feedback and required outputs are verified.                                          |
|V7 |C7        |A failed occupancy sensor is treated as clear and an opening command is issued.                   |`Sensor_Failure=TRUE; Open_Command=TRUE; Fail_Safe_Active=FALSE`                                                       |`TRUE → (FALSE ∧ FALSE)` is FALSE.             |Suppress opening, invalidate clearance, activate fail-safe controls, and request maintenance.                                         |
|V8 |C8        |A failed barrier is incorrectly acknowledged as closed and train permission remains enabled.      |`Barrier_Failure=TRUE; Train_Permission=TRUE; Fail_Safe_Active=FALSE`                                                  |`TRUE → (FALSE ∧ FALSE)` is FALSE.             |Withdraw/withhold permission, maintain available warnings/STOP, and request intervention.                                             |
|V9 |C9        |After communication loss, a cached remote opening message is accepted and normal mode continues.  |`Communication_Lost=TRUE; Remote_Open_Accepted=TRUE; Fail_Safe_Active=FALSE`                                           |`TRUE → (FALSE ∧ FALSE)` is FALSE.             |Reject the stale request, enter local fail-safe operation, and queue an alert.                                                        |
|V10|C10       |Conflicting sensor readings are ignored and clearance is confirmed without protective action.     |`Invalid_Readings=TRUE; Clearance_Confirmed=TRUE; Fail_Safe_Active=FALSE`                                              |`TRUE → (FALSE ∧ FALSE)` is FALSE.             |Invalidate clearance, inhibit opening, retain road protection where possible, and diagnose sensors.                                   |
|V11|C11       |An emergency is active, but normal-mode logic grants permission and an opening command.           |`Emergency_Active=TRUE; Train_Permission=TRUE; Open_Command=TRUE; Fail_Safe_Active=FALSE`                              |`TRUE → (FALSE ∧ FALSE ∧ FALSE)` is FALSE.     |Override normal release commands, invoke emergency handling, and alert the operator.                                                  |
|V12|C12       |A road signal remains permissive while a train is approaching and barriers are not confirmed open.|`Train_Approaching=TRUE; Train_Passing=FALSE; All_Barriers_Open_Confirmed=FALSE; Road_Stop=FALSE`                      |`(TRUE ∨ FALSE ∨ TRUE) → FALSE` is FALSE.      |Command STOP, inhibit train permission if needed, and escalate any signal fault.                                                      |
