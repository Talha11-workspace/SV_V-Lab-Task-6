## Verification procedure

1. Use a simulator or fault-injection test environment, never live railway equipment.
2. Inject the stated event/fault and variable values.
3. Evaluate the linked constraint at the defined checkpoint.
4. Require a constraint-violation record with ID, timestamp, readings and command state.
5. Check the expected protective response using actual feedback, not command acknowledgment alone.
6. Re-run with a compliant valuation to check that the monitor does not raise a false violation.

Example compliant C1 valuation: Train_Present = TRUE and Barrier_Open = FALSE makes the implication TRUE. Counterexamples establish that the monitor should detect forbidden behavior; they do not establish that the implemented controller is correct.
